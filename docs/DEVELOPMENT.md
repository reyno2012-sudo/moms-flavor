# 妈妈的味道 V0.2 开发计划

以 [产品交接](PRODUCT.md) 和 [既有路线](ROADMAP.md) 为需求基线。保留 V0.1 原始 PRD 和 V0.2 五个入口。此文档记录研发决策、接口和验收口径。

## 技术架构提案

| 层 | 本地研发 | iOS、Android 内测方案 |
|---|---|---|
| 客户端 | 继续维护现有 HTML、CSS、JavaScript，验证同一套交互和 API | React Native、Expo Router、TypeScript。五个底部入口各有独立导航栈，录入、校对和详情进入栈内页面 |
| 应用数据 | JavaScript 共享筛选、可见性和文本字段契约 | 以 API 契约和设计令牌为迁移单位。草稿允许离线编辑，敏感会话凭证存入 SecureStore，退出时清除账号缓存 |
| 服务 | Node HTTP 与 SQLite，本地数据库可重启复用 | Node TypeScript 模块化单体。服务端校验身份和成员角色，PostgreSQL 用于事务及第二层行级权限，独立任务进程处理媒体和 AI |
| 认证 | 本地用户名密码与 HttpOnly 会话 Cookie | 邮箱或手机验证码、短期访问令牌、可撤销轮换凭证。服务选择和短信成本在试点前确认 |
| 素材和 AI | 文本来源明确同意后提交服务端整理，人工校对后才可保存和投稿 | 私有对象存储、分段上传、授权后短时读取。转写与抽帧可重试，任务记录素材授权、来源位置、模型版本和人工修改 |
| 发现 | 审核通过的公开快照；兴趣区域、真实互动、新鲜度和作者多样性 | PostgreSQL 公共投影与候选召回，按需要引入中文全文索引。行为日志仅含公开快照 ID 和最少事件属性 |

Expo 可共享导航、页面和客户端业务逻辑。优先迁移拍摄、录音、锁屏陪做、深链接四个需要原生能力的流程。Web 端继续承担界面回归与审核入口。Flutter 和原生双端都是可选方案，但会增加当前 JS 模型、校验和工具链的迁移工作。原生工程在技术栈确认后开始，先用 Android 开发构建和 iOS 真机开发构建验证媒体授权、弱网及进度恢复。

[Expo Router](https://docs.expo.dev/router/introduction/) · [SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/) · [Node SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html) · [PostgreSQL 行级权限](https://www.postgresql.org/docs/current/ddl-rowsecurity.html) · [OpenAI 结构化输出](https://platform.openai.com/docs/guides/structured-outputs)

## 权限、发布和数据边界

| 对象 | 可读 | 可写 |
|---|---|---|
| 个人菜谱原稿和 AI 任务 | 创建者 | 创建者。AI 任务只可在本人同意后读取本人提交的素材 |
| 家庭菜谱 | 该家庭当前成员 | 菜谱创建者且仍为成员。家庭拥有者管理邀请，家庭成员不能替对方公开 |
| 待审核公开快照 | 投稿者和审核员 | 投稿者撤回。审核员通过或拒绝，记录决定和时间 |
| 已通过公开快照 | 所有人 | 投稿者撤回。内容修改需要新快照和新审核 |
| 私有素材 | 所属菜谱授权范围内且素材同意有效 | 上传者管理。公共媒体从明确选择的独立副本发布 |

家乡、常住城市和菜谱所属地域是独立字段。提交公开时用户须预览并确认，用字段白名单构造快照，服务端另存原稿。快照使用独立 ID，可公开标题、分类、地域和单独填写的公开说明，后续可逐项加入作者确认的食材、步骤、化名和媒体副本。家庭标识、真实姓名、原音和私有备注留在原稿。公共详情、搜索、地域和推荐共用审核通过且未撤回的读取范围。成员身份撤销后立即重查权限。撤回先更新快照状态，再删除公共索引或缓存的副本。

## 开发与验收顺序

| 阶段 | 交付与实现位置 | 放行验收 |
|---|---|---|
| S0 交互基线 | 先运行 `npm.cmd run dev`、`npm.cmd test`。继续迭代 `src/app.js` 和 `src/style.css`。通过下表检查 18 个场景 | 五项导航完整，支持单列与双列、实时搜索、地域独立选择、校对和分享确认。窄屏无横向溢出，键盘可完成主要流程 |
| S1 本地服务 | `server.mjs` 分发 API，`server/api.mjs` 执行授权和业务校验，`server/schema.sql` 维护 SQLite 数据模型。认证、家庭邀请、三档保存、复核、撤回及推荐接到原界面 | `npm.cmd test` 校验创建者、家庭成员、陌生账号、游客和审核员。验证公开 ID 与原稿 ID 独立、退出及重启、并发重放和撤回 |
| S2 媒体与 AI | `server/ai.mjs` 加入文本整理适配器。原生端确认后，加入授权录制、上传、后台任务、逐字稿及帧时间。产出字段保存证据与未知状态，编辑后重新确认 | 未授权时无供应商调用。证据能在原文中找到，未知量和时间保留。任务失败可恢复原稿并走手动流程。使用经过同意的样本实测 |
| S3 社区与推荐 | 持久化关注、收藏、评论、举报、屏蔽和公开互动。公共候选以地域和关注召回，综合新鲜度、质量及互动，做作者多样性。上线前加入后台审核、分页和中文搜索 | 审核和撤回贯穿详情、地域、搜索和推荐。举报可追踪，屏蔽生效，关闭个性化仍能浏览按时间排序的公开内容 |
| S4 陪做与数据权利 | 在 `CookSession` 固定菜谱版本，保存步骤、剩余时间和复刻反馈。个人数据页加入导出和删除，家庭空间加入角色调整、成员退出和成员撤销 | 锁屏、来电、退出或离线后恢复会话。版本变化不串改已开始的陪做。数据导出不混入他人原稿。删除同步移除公开投影及素材访问 |
| S5 双端内测 | 原生端按下表逐屏迁移，使用 PostgreSQL 运行现有权限用例。完成中文输入、无障碍、双平台采集授权、弱网、备份恢复、审核和 AI 成本验证 | 使用同意参与的家庭与创作者。跟踪首次记录完成率、月度成功复刻家庭数、公开内容到复刻转化、审核时长和单菜谱整理成本。发布主体和条款另行确认 |

## 服务接口约定

- `/api/session`、`/api/register`、`/api/login`、`/api/logout` 管理本地身份，服务端以会话确定操作者。
- `/api/families`、`/api/families/:id/invites`、`/api/join` 管理家庭和单次邀请。家庭查询按当前成员过滤。
- `/api/recipes` 保存个人原稿、家庭菜谱或公开投稿。`/api/recipes/:id` 根据原稿或快照权限读取。`/api/publications/:id/withdraw` 撤回，`/api/review` 处理待审。
- `/api/feed` 根据全国、地域、关注、最新、关键词、菜系和类别查询审核后的快照。`/api/interactions` 只接受仍可见的公开快照或作者。
- `/api/ai/organize` 接收明确授权的文本，并返回带证据和未知状态的整理结果。请求时限内失败可手动继续，生产任务还需持久队列和授权重查。

接口返回 JSON。鉴权失败返回 `401`，调用无审核权限的操作返回 `403`，不可见对象返回 `404`，重复状态变更返回 `409`，字段校验失败返回 `400`。菜谱保存提供幂等标识，后续为媒体上传、AI 任务和评论补充幂等逻辑。SQLite 服务仅监听回环地址，生产部署涉及的 TLS、限流、监控、备份和供应商审批在 S5 验收。
